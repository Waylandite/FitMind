# FitMind 周报与趋势统计设计

## 1. 模块定位

周报与趋势模块把已经确认保存的训练、饮食和身体状态转换为可比较指标。

模块包含两个入口：

- 聊天入口：识别 `weekly_trend_report`，展示 Agent 查询过程并生成简洁周报。
- 独立页面：调用确定性统计 API，展示指标卡片和趋势图，不调用 LLM。

周报实时计算，不新增报告表，也不保存快照。

## 2. 周期规则

- 当前周：本周一至今天，对比上周一至相同星期几。
- 历史周：所在周的周一至周日，对比前一完整自然周。
- `anchor_date` 默认当天，可指定历史日期，不能指定未来日期。
- 每日序列始终返回周一至周日七个位置；当前周尚未到来的日期返回空值。

## 3. 指标口径

| 维度 | 指标 | 口径 |
| --- | --- | --- |
| 训练 | 训练次数 | 周期内训练主记录数量，同日多次分别计数 |
| 训练 | 训练天数 | 有训练记录的去重日期数 |
| 训练 | 完成次数 | `completion_status=completed` 的记录数 |
| 训练 | 已知时长 | 只累加非空 `duration_minutes`，全部缺失时返回空值 |
| 训练 | 力量组数 | 力量动作中非空 `sets_count` 之和 |
| 训练 | 有氧动作数 | `exercise_type=cardio` 的动作明细数 |
| 饮食 | 记录天数 | 有饮食记录的日期数 |
| 饮食 | 营养日均值 | 只使用该字段非空的记录日计算，不补零 |
| 恢复 | 记录天数 | 有身体状态记录的日期数 |
| 恢复 | 睡眠/疲劳/压力/酸痛均值 | 各字段按自己的非空样本计算 |
| 恢复 | 体重变化 | 周期内至少两个体重点时，最后值减最早值 |

每个指标返回本期值、上期值、绝对变化和变化率。上期值为零或任一期缺失时，变化率返回 `null`。

动作部位映射由训练历史和周报共享。复合动作可以计入多个部位；无法识别的动作进入“其他”。

## 4. API

```http
GET /api/v1/analytics/weekly?user_id=1&anchor_date=2026-07-30
```

响应包含：

- `period`：当前周期、对比周期和是否为当前周。
- `coverage`：训练、饮食、身体状态记录覆盖天数。
- `training`、`nutrition`、`recovery`：本期、上期和变化指标。
- `daily_series`：周一至周日的本期/上期每日数据。
- `muscle_distribution`：本期/上期动作部位分布。

接口只读取业务事实，不写对话日志，不调用 LLM。

## 5. 聊天工作流

SSE 节点顺序：

```text
weekly_report_start
  → query_weekly_workouts
  → query_weekly_nutrition
  → query_weekly_body_status
  → aggregate_weekly_metrics
  → weekly_report_llm
  → weekly_report_complete
```

LLM 只接收已经计算好的 JSON 指标，负责组织结论和行动建议。它不得重新计算数值、推断缺失数据、计算训练容量或进行医疗诊断。
